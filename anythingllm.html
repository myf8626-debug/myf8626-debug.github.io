Resume Protocol 关注候选人事实是否有来源。这个扩展接着检查：已有来源的事实能否被检索出来，又会不会在重排或截断时丢失。基于 AnythingLLM，在 AI 辅助下实现评测界面、任务 API、记录存储与混合召回。

先定位召回问题，再考虑重排

重排只能处理已有候选。我先把候选池、原始 Top K、最终 Top K 分开评测，逐题对照标注依据，区分“没有召回”和“召回后被丢弃”。不能因为最终答案不好，就直接认定需要更换模型。

  • 前后端评测流程：React 配置与结果界面 → Express API → SQLite 数据集、运行及逐题记录。支持幂等提交、取消、失败回退和 JSON 导出；取消后的迟到结果不能覆盖任务状态。
  • 补充候选来源：在评测入口加入 pgvector 向量召回与 BM25 关键词召回，用 RRF 按排名融合，保留来源渠道。中文双字词项与英文标识符用于匹配；未改写上游文档切分器。
  • 范围与可比性：服务端按工作空间与用户绑定记录，复用上游鉴权；数据集版本和参数随运行保存，不兼容的基线不直接比较增益。

技术栈：React / JavaScript、Node.js / Express、SQLite、PostgreSQL / pgvector、BM25、RRF；复用上游 Prisma、Embedding 适配与本地交叉编码器推理。

真实模型跑通，也保留退化结果

multilingual-e5-small 实际生成 384 维向量并写入 pgvector；MiniLM 实际推理。12 段合成资料、20 道开发验收题，candidateK=8、最终 K=3；Recall / MRR 只统计其中 17 道有答案题，3 道无答案题单独记录。
